Project Reflection

In this project, I practiced using Git and GitHub to make changes to a website. I started on the main branch and created a separate branch called footer so I could work on the footer without changing the main version right away. I edited index.html and added a new paragraph to the footer.

While I was working in VS Code, I saw a message saying the file had been updated and my changes could not be saved as they were. I compared the file versions, checked the latest content, and made sure my footer change was still there. I also used git status to see which files had changed before I pushed my work. This reminded me to check the file and Git status before committing changes.

After pushing the footer branch to GitHub, I opened a pull request to merge it into main. I added a short description explaining what I changed. GitHub showed that the branches could be merged automatically, so I reviewed the change and merged the pull request. Then I checked the repository to make sure the updated footer was on main.

This project helped me understand how branches keep work organized and how pull requests let people review changes before they become part of the main branch. It also helped me get more comfortable with commits, pushing changes, and checking my work in GitHub. I learned to slow down when I see a file warning, compare the versions, and confirm that the change I want to keep is saved.
